# codex-reset 流量分析（2026-10-29 10:20 采）

> 数据源：`/www/wwwlogs/codex-reset.opentunnel.asia.log`（nginx combined 格式）
> ⚠ 客户端 IP 全部是 `127.0.0.1`（走 Cloudflare Tunnel，nginx 只看到本地回环），
> **因此无法统计独立访客（UV）**，只能按请求/UA/referrer 拆。要算 UV 必须先补真实 IP 回填。

## 一、核心结论

**「一天几千请求」里 9 成以上是前端自己的轮询，不是人。**

| 日期 | 总请求 | API | 页面 | API 占比 |
|---|---|---|---|---|
| 10-29（00:00–10:20，10.3 h） | 2,107 | 1,972 | 135 | **93.6%** |
| 10-28（全天） | 11,350 | 9,345 | 2,005 | 82.3% |
| 10-27 | 7,186 | — | — | — |

近 7 天每日：`4577 / 4708 / 4712 / 4799 / 7186 / 11350 / 2107(未满)`
→ 今天按小时线性外推约 **4,900/天**，和前 5 天基线（4.5k–4.8k）一致，**并没有变多**。

## 二、请求都在打什么

今日 top 路径：

| 路径 | 次数 | 折合频率 |
|---|---|---|
| `/api/forecast` | 620 | ≈1 次/分钟 |
| `/api/status` | 616 | ≈1 次/分钟 |
| `/api/feed` | 611 | ≈1 次/分钟 |
| `/api/health` | 123 | ≈1 次/5 分钟 |
| `/`（首页） | 15 | 真访问 |
| 静态资源（js/css/svg） | 各 5 | 真访问 |

→ 每 20 秒一轮 `forecast+status+feed`，约 **3.1 请求/分钟 = 4,500/天**。
这就是「几千请求」的全部来源：**一个常开的标签页**（或监控工具）。

今日每小时几乎恒定（00 时 199、06 时 197、09 时 256），这种「连凌晨都平」的曲线
是轮询的典型特征——真人流量一定有昼夜起伏。

## 三、昨日 11,350 的异常

- 页面请求 2,005（今日仅 135），API 9,345
- API 9,345/24h ≈ **6.5 次/分钟** ≈ 今日（3.1/min）的 2.1 倍
  → 发布当天大概开了 **两个** 常驻标签页（referrer 显示 5,779 来自首页、3,896 来自 `/status`，正好两个来源）
- Googlebot 110 次、GoogleOther 81 次（今日分别 20 / 32），是发帖当天 Google 首次来抓
- 真人线索几乎没有：Twitter UA 全天只有 1 次

## 四、真实流量到底有多少

| 指标 | 今日（10h） | 昨日（24h） |
|---|---|---|
| 页面请求 | 135 | 2,005 |
| 首页 `/` 加载 | 15 | 108 |
| Googlebot | 20 | 110 |
| GoogleOther | 32 | 81 |
| Twitter/iPhone UA | 38 | 1 |
| 外链 referrer（t.co） | 2 | 0 |

**推断真实访客是「十几个」量级**，而不是几千。其中：
- `Twitter UA 38 次` + `t.co 2 次` → X 那边点进来的人极少（X 帖子只有 12 浏览）
- Google 抓取在正常化（110 → 20/10h）

## 五、建议（按收益排序）

1. **轮询降频 + 只在可见时轮询**：`forecast/status/feed` 每 60–120 秒一次，并监听
   `document.visibilityState`，页面切到后台就停。请求量可砍 **60–90%**，也省用户流量/电。
2. **补真实 IP**：nginx 加
   `set_real_ip_from <Cloudflare 网段>; real_ip_header CF-Connecting-IP;`
   之后日志才有真 IP，才能算 UV / 地域 / 单访客请求数。这是做任何正经分析的前提。
3. **监控与真人分离**：给健康检查单独 UA（如 `codex-reset-monitor/1.0`）或独立子域名，
   分析时一条 grep 就能排除，不用再猜。
4. **看板直接用 Cloudflare Analytics**（免费、有 UV/国家/缓存命中），比扒 nginx 日志省事；
   自建的话写个 `/__stats` 读日志汇总即可。
5. **sitemap**：GSC 连续第 2 天「无法抓取」（我方 `curl` 正常返回 200 + 合法 XML），
   明天仍红就删了重提交。

## 六、复现命令

```bash
ssh -i ~/.ssh/sketchive_deploy_ed25519 root@101.133.168.66
log=/www/wwwlogs/codex-reset.opentunnel.asia.log
d=$(date +%d/%b/%Y)

# 总量 / API 占比
grep -c "$d" $log
grep "$d" $log | grep -c "/api/"
grep "$d" $log | grep -vc "/api/"

# 按小时
grep "$d" $log | sed -E 's/.*:([0-9]{2}):[0-9]{2}:[0-9]{2}.*/\1/' | sort | uniq -c

# 顶部路径（去掉 query）
grep "$d" $log | cut -d'"' -f2 | awk '{print $2}' | sed 's/?.*//' | sort | uniq -c | sort -rn | head

# 机器人
grep "$d" $log | grep -ac "Googlebot"
grep "$d" $log | grep -ac "GoogleOther"

# 外链 referrer
grep "$d" $log | cut -d'"' -f4 | grep -v '^-$' | sort | uniq -c | sort -rn
```
